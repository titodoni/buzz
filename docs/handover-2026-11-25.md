## 1. Work Completed in This Session

### 1.1 Fixed Friend Request Visibility & Pending State in the Buddy List (`v0.1.2`)

**Root cause:** `.ym-list` in [`app/globals.css`](../app/globals.css) had `min-height: 100%` inside `.ym-content { height: 100%; }`, forcing `FriendList` to occupy 100% of the scroll container height and pushing `PendingRequests` completely below the fold at all window sizes. Additionally, `FriendSearch` ignored existing relationship state, hiding pending/friend context after search or reload.

**Changes implemented:**
- **Buddy List layout ([`app/globals.css`](../app/globals.css), [`components/BuddyList.tsx`](../components/BuddyList.tsx)):**
  - Wrapped the Buddy List body in `.ym-buddy` (`display: flex; flex-direction: column; min-height: 100%;`) and switched `.ym-list` to `flex: 1`.
  - Filtered `incoming` requests in `BuddyList` against `ignoredIds` (`visibleIncoming`) and moved `<PendingRequests incoming={visibleIncoming} onChanged={reload} />` directly above `<FriendList />`.
- **Outgoing Friend Requests in the Buddy List ([`lib/friends/arrange.ts`](../lib/friends/arrange.ts), [`components/friends/FriendList.tsx`](../components/friends/FriendList.tsx), [`components/friends/PendingRequests.tsx`](../components/friends/PendingRequests.tsx)):**
  - Added `filterPendingFriends()` in `lib/friends/arrange.ts` to filter and alphabetically sort outgoing pending requests with the search box.
  - Updated `FriendList` (`pending = []` prop, fed `outgoing` from `BuddyList`) to render outgoing Friend Requests in the default `Friends` Group with suffix `(pending)`. When all accepted Friends belong to custom Groups (or none are in the default group), `FriendList` still creates the default group header so outgoing `(pending)` rows remain visible.
  - Kept `PendingRequests` accepting optional `outgoing` (default `[]`) and passed only `visibleIncoming` from `BuddyList` so outgoing requests appear inline in the Buddy List rather than duplicated in the banner above.
- **Inline relationship actions in Search ([`lib/friends/search.ts`](../lib/friends/search.ts), [`components/friends/FriendSearch.tsx`](../components/friends/FriendSearch.tsx)):**
  - Added `searchResultRelation(userId, lists, justSentIds)` returning `"friend"`, `"incoming"` (with `friendshipId`), `"outgoing"` (with optional `friendshipId` and optimistic `sentIds` support), or `"none"`.
  - `FriendSearch` now keeps results visible after clicking `Add`, renders `Accept` / `Decline` buttons directly when an incoming Friend Request already exists from that person, `(pending)` for outgoing requests, and `Friend` for existing Friends.

### 1.2 Display Name & Optional Avatar on Sign-Up (`v0.1.2`)

- **Sign-Up UI ([`components/auth/AuthForm.tsx`](../components/auth/AuthForm.tsx)):**
  - Added required `Display name` field (validated with `isValidDisplayName`, max length `DISPLAY_NAME_MAX` = 50, live character counter) and optional Avatar file picker (`Choose picture` / `Remove`, `checkAvatar` validation for PNG/JPEG/WebP up to 2 MB, preview defaulting to `/avatars/default.png`) in `signup` mode.
  - Added `Edit Profile...` (`router.push("/profile/")`) to the Buddy List `Messenger` menu in [`components/BuddyList.tsx`](../components/BuddyList.tsx).
- **Sign-Up Session Flow ([`lib/auth/session.ts`](../lib/auth/session.ts)):**
  - Extended `signUp(email, password, opts?: SignUpOptions)` to validate `opts.avatarFile` before `auth.signUp()`, pass trimmed `display_name` in `options.data`, update `public.profiles.display_name` directly when an active session is returned (email confirmation off), and call `uploadAvatar(user.id, opts.avatarFile)` (redirecting to `/profile/` with notice if avatar upload fails).
- **Database Trigger Migration ([`supabase/migrations/20261125034400_signup_display_name.sql`](../supabase/migrations/20261125034400_signup_display_name.sql)):**
  - Updated `public.handle_new_user()` (`SECURITY DEFINER`, `set search_path = ''`) to read `new.raw_user_meta_data ->> 'display_name'` (trimmed, max 50 chars), falling back to email prefix, then `'buddy'`.
  - Kept `revoke execute on function public.handle_new_user() from public, anon, authenticated;`.
- **Note on email confirmation:** Per user decision for beta testing, Supabase email confirmation remains disabled in the hosted project (`needsConfirmation === false` at sign-up). Re-enabling confirmation later works automatically via the trigger migration because `handle_new_user()` reads `raw_user_meta_data`.
